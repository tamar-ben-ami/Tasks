# Triage the inbox

`inbox.md` exists so nothing is lost to indecision about where it goes. This is
the step that pays that back.

## Steps

1. Read `inbox.md`. Ignore the blank `- [ ]` template lines — only real items
   count.

2. For each item, decide where it belongs using the routing table in
   `CLAUDE.md`. Then do one of four things:

   - **File it** — move it into the right list, in the right section. Phrase it
     as an action ("call about the boiler") rather than a fragment ("boiler").
   - **Make it a date** — if it has a deadline, put it in that file's table with
     the date in a tracked column, not as a loose checkbox.
   - **Drop it** — already done, or no longer relevant. Say what you dropped.
   - **Leave it** — genuinely ambiguous, or needs a decision only the user can
     make. Leave it in the inbox and ask.

3. Move anything explicitly "not now" into the **Someday / maybe** section at the
   bottom of `inbox.md` rather than filing it.

4. Remove the filed lines from the inbox. Leave the blank template lines and the
   Someday section in place.

5. Report as a short list: item → where it went. Group anything you left behind
   with the question you need answered.

## Notes

- One item can imply several. "Trip to Berlin in March" becomes a travel block in
  `family.md`, a passport-validity check in `documents.md`, and travel cover in
  `insurance.md`. Cross-link rather than duplicating.
- Don't invent detail to make an item look complete. If the note says "call about
  insurance thing", file it as-is and ask which policy.
